# 基础卡片

1.14.0 的 `show_information` 支持在同一引用块内展示多条信息；`show_cards` 继续展示双列紧凑卡片和混合布局。只展示一张紧凑卡片时仍占双列网格中的一个位置。Agent 一次提供 1 至 6 张卡片，只填有真实依据的字段；模型不生成 UI 节点。

一张卡片可以包含：抬头与图标、主要信息、事实行、资源、趋势数据、步骤进度、底部信息和最多两个真实网页操作。这些部分自由组合，因此日程、文件、经营数据、物流、天气、设备状态等场景共用一种视觉样式。没有数据的部分省略，不补造内容。

```json
{
  "cards": [
    {
      "title": "订单进度",
      "subtitle": "订单号 DP784392",
      "icon": "shippingbox",
      "accent": "orange",
      "headline": "运输中",
      "detail": "预计周五送达",
      "steps": [{"title":"已发货"},{"title":"运输中"},{"title":"派送中"}],
      "current_step": 1
    }
  ]
}
```

展示已核实的独立要点、结论、说明或摘录时，优先调用 `show_information`；多个卡片混排时仍可在 `show_cards` 中使用 `type: "information"`。标题必填，副标题没有真实来源或上下文时可省略。单段使用 `content`；分条使用 `contents` 数组（1 至 8 条），两者不能同时传入，内容合计最多 1200 字。每条单独排版，条目之间留 6 点间距；引用区左侧使用加粗的系统灰色竖线，正文使用 12 点次要文字色，左对齐并随文字高度增长。信息卡在混合列表中独占一行，前后的紧凑卡片仍保持双列。用户明确只要文字、简单闲聊或单句事实时不强行展示卡片。

```json
{
  "title": "研究结论",
  "subtitle": "来源：已核实的报告",
  "contents": [
    "第一条已核实的结论。",
    "第二条独立信息。"
  ]
}
```

上例是 `show_information` 的参数。旧的单段 `content` 调用仍然有效；混排时在 `show_cards.cards[]` 的信息卡对象中使用相同的 `content` 或 `contents` 字段。

插件首页展示六张紧凑预览卡和一张信息卡示例；组件目录只列基础组件。`show_cards` 的网页链接仅接受 HTTP(S)。布局与内容组合由 `main.js` 定义，输出通用的 `cuebo-v1` 节点，无需新增 App 原生组件。紧凑卡片的长底部信息自动改为竖排；折线图和面积图使用平滑曲线。紧凑卡片只展示短摘要：过长文字加省略号，事实和底部信息各最多显示两项；返回值的 `shortenedCards` 给出被缩短的卡片序号。Agent 默认只补一句结论或必要异常，用户要明细时再展开。紧凑卡片按列宽固定 1:1 尺寸，`bottomChildren` 将横条固定在底边。卡片表面不放按钮或单独可点的资源；整卡点击打开半弹层，`detailChildren` 展示未截断的原始字段，资源链接与操作也只在弹层里。App 随附的初始版本可通过插件商店更新。
